## Scope and operating constraints

HyperVXNdisFilter 0.3.3 is an experimental **ordinary NDIS 6.40-6.89 optional modifying Ethernet Lightweight Filter (LWF)** for **all Hyper-V management-OS Ethernet adapters associated with HNS networks of type ICS**. Default Switch and WSL (Hyper-V firewall) are examples, not a name/GUID allowlist or mandatory pair. It is **not a Hyper-V switch extension**. The same SYS additionally registers WFP callouts at **FWPM_LAYER_IPFORWARD_V4/V6** for **all traffic presented at those forwarding layers, independently of NDIS bindings or HNS targets**; WFP supplements, never replaces, the NDIS path. The old switch-extension approach could not be enabled on the automatic ICS switch; do not restore it or use `Enable-VMSwitchExtension`.

- Work in the separate `C:\hyperv` repository. `C:\portmaster_v3` is the compatibility/reference project, not a build dependency; do not modify it as part of HyperVXNdisFilter work.
- **Create commits only when explicitly requested.** The working branch is `master`; inspect the current branch/status before Git mutations. Amend the last commit only when explicitly requested, and do not infer permission to push or force-push from permission to commit/amend.
- **Build the kernel driver in release mode only.**
- The user authorizes agent-run driver installation/loading/binding, native setup notify registration, device access, and live traffic tests using `192.168.219.15`; a separate request for each such test is not required. Use native Install.exe/Uninstall.exe and retain recovery/cleanup evidence. Offline builds and tests do not require installation.
- Network configuration changes needed for this work are permitted, including HNS/ICS/NAT, switches, VM placement, IP/routes, and adapter bindings. Inspect and record the affected state first, preserve unrelated connectivity, and restore temporary diagnostic changes. Do not change certificate stores, boot/security policy, or Driver Verifier without separate explicit authorization.
- `hyperv_monitor.exe` first opens the existing device. If it is absent, the monitor may load a temporary kernel service from `HyperVXNdisFilter.sys` beside its EXE or `--sys PATH`. A newly created service uses `Parameters\StandaloneWfp=1` for WFP/control-device-only operation, with no NDIS registration or bindings. Close/join all device I/O before stopping a driver started by this monitor; delete only a service created by it. Never reconfigure an existing service, replace an installed SYS, or stop a previously running driver. Busy-device/access-denied errors do not trigger loading. Full NDIS installation/removal still belongs to the native setup EXEs. Agent-run monitor sessions may omit `--duration` if tracked and cleaned up; `--help` is offline-safe.

This filter sees the **host-vNIC send/receive path**, not necessarily VM-to-VM traffic inside the switch. Public direction and endpoints describe the **guest/Sandbox side** of this path, not host NDIS direction, process ownership, or an entire VM's traffic.

## Architecture and invariants

### Kernel data path: Rust owns policy and the native WDK boundary

The complete kernel, including native WDK callbacks and NBL/NB/MDL/IRP operations, is Rust. User-mode setup/notify/monitor remain C++. `driver/build.rs` uses windows-drivers-rs `wdk-build` and build-only bindgen/libclang against the installed WDK; do not hand-maintain WDK layouts. Rust uses the `no_std`-compatible `likely_stable` crate. Hints favor IPv4 TCP/UDP and allocation success, not a particular TCP/UDP split, verdict, cache-hit rate or offload profile. Keep input checks and ownership cleanup. A failed `ExAllocatePool2` must bugcheck; other allocation APIs are assumed to succeed without OOM checks. Never replace a hint with `__assume` or unreachable error paths.

`driver/src/native_ndis.rs`, `native_device.rs`, `native_registry.rs`, `native_packet.rs`, and `native.rs` are the Rust WDK ABI boundary: NDIS registration/callbacks, target attach gate, device I/O, locks/timer, NBL-local ownership contexts and copy pools, OIDs, and pause/restart/detach. It calls the `Hv*` exports in `driver/src/lib.rs`, which bridge to the Rust policy engine. The Rust driver is a `no_std` static library; `cargo build` alone does **not** produce the final `.sys`. The kernel image is `HyperVXNdisFilter.sys`, with matching `HyperVXNdisFilter.pdb`. The complete product rename also uses `HyperVXNdisFilter.inf`, `HyperVXNdisFilter.cat`, `HyperVXNdisFilterNotify.dll`, service/device `HyperVXNdisFilter`, startup event `Global\HyperVXNdisFilter.DriverReady`, NetCfg component `hyperv_xndis_filter`, and header `HyperVXNdisFilter.hpp` / namespace `hypervxndisfilter`. Setup/notify C++ uses namespace `hyperv_xndis_filter`; environment variables use prefix `HYPERVXNDISFILTER_`. There are no old-name aliases. Wire/API version remains 0.3.3.0, and package/notify GUIDs remain unchanged. Start a rename rebuild with a clean dist; do not mix package generations. The installer detects a previous-name component by the stable filter GUID and refuses it. Remove a prior installation only with its matching old tools, explicitly authorized; never rename or replace an installed SYS. Raw historical logs and signed backups are evidence, not current build inputs; do not rewrite them to claim renamed-package validation.

`policy/src/packet.rs` parses bounded Ethernet/VLAN/IPv4/IPv6/TCP/UDP data and normalizes guest/peer endpoints. Its internal `NdisPath` decodes native-Rust values (0=Send, 1=Receive) and maps them to the opposite public guest direction (Send=Inbound, Receive=Outbound). `policy/src/engine.rs` manages pending decisions, event streams, per-interface TCP/UDP IPv4/IPv6 tuple TTL caches, and bandwidth aggregation. `protocol/src/lib.rs` owns explicit byte encoding and command validation; never serialize native C/Rust struct layout onto the wire.

`driver/src/wfp.rs` owns WFP management, reconciliation/retry/teardown, classification and packet-ownership decisions, reinjection routing and failure accounting; `driver/src/wfp_checksum.rs` owns protocol/checksum restoration. `driver/src/native_wfp.rs` owns native WDK descriptor construction/callbacks, synchronization/device storage and NB/NBL/MDL/context access in Rust. These manage an unnamed private registration device, two runtime callouts, forward/network injection handles per IP family, and a dynamic BFE session with two unconditional IPFORWARD filters in one private sublayer, requesting `0x7100` (one filter per address family); `FWPM_SUBLAYER_UNIVERSAL` is `0x8000`; BFE may adjust the effective weight if necessary. WFP covers every source interface reaching those layers, not an HNS/LWF target list. BFE callbacks schedule PASSIVE reconciliation with failure-only retries. No persistent filters, NETIO interface inventory/notifications, per-interface reconnect workers, generations or network/registry repair. Existing LogLine events report readiness; fail-closed cannot protect a layer that is not classifying. WFP source index is retained in events/statistics; direction is always 0 and local/remote are observed IP source/destination. Replies normally belong to another source index/tuple; do not invent guest/initiator identity. NDIS keeps exact HNS ICS binding admission and guest-relative directions. There is no cross-path packet deduplication guarantee.

NDIS and WFP use one Engine and common pending/event/cache/bandwidth structures, without keyed source-specific connection copies. The API verdict ID directly selects one Pending containing the actual NBL address, not a separate opaque token. NDIS/WFP ownership metadata is attached to the owned NBL using NdisAllocateNetBufferListContext and removed before returning/freeing it. No native-Rust token allocations, hash buckets or generation/CAS handoff. Once pending ownership is published, the classifier never dereferences that NBL again; early verdicts finish through the normal completion/injection path. The packet context has no policy/connection identity. NDIS completion/return validates its own context and module, preserving original/copy ownership and inline-completion safety. WFP clones/reassemblies have no HV_ADAPTER dependency and hold manager packet rundown until free/injection completion. Ordinary clones use FwpsAllocateCloneNetBufferList0/FwpsFreeCloneNetBufferList0; fragment groups use FwpsReassembleForwardFragmentGroup0/FwpsFreeNetBufferList0 and never cache. HvClassifyIp reuses the raw-IP parser with zero L2 length and no send cancel ID. Pending returns BLOCK|ABSORB; ordinary allow reinjects with FwpsInjectForwardAsync0, original destination index and available compartment. Inbound/outbound weak-host pass-through uses FwpsInjectNetworkReceiveAsync0/FwpsInjectNetworkSendAsync0 with per-family network handles; retain the original destination sub-interface internally for receive injection and check both handle kinds for injection exemptions. Current/previous self-injection states for either handle kind immediately soft-permit the original before WFP policy even without a controller. All other forwarded IP traffic follows normal policy, independently of source interface index. The non-default `wfp-fragment-diagnostic` feature separately soft-permits ungrouped IPv4 fragments before policy and must stay disabled in normal release packages. Exempt packets bypass WFP events, cache and bandwidth, but do not override other WFP filters or the NDIS path. Before pending reinjection, software-complete the IPv4 header and ordinary TCP/UDP/ICMPv4/ICMPv6 checksums on every NB independently of receive-success OOB; walk split MDLs without changing offsets or non-checksum bytes, and use the upper-layer length after IPv6 extensions in the pseudo-header. Clear checksum OOB only for software-completed datagrams. Fragments retain transport checksums; retain original scalar segmentation/coalescing state before cloning and preserve logical LSO/RSC offload profiles instead of fabricating whole-datagram transport checksums. Injection submit/completion failures use bounded existing Warning LogLine events (first and power-of-two failure counts per controller session), not per-verdict acknowledgements. Only synchronous nonpending allows soft-permit the original. Policy finish and WFP/NDIS calls occur outside policy/classification locks. Stop closes callout admission, drains management/classification, invalidates/drains pending forwarding records, waits packet/injection rundown, then unregisters/destroys WFP objects before deleting the private device. FWPM APIs are PASSIVE-only and never under adapter, diagnostic, policy or I/O fast-mutex locks. Offline native suites in `monitor/tests/native_rust` compile the production NDIS/device/packet/WFP Rust modules against actual generated WDK layouts with fake OS calls. WFP manager/checksum and native layers execute together. Never retain a duplicate C++ implementation or fake WDK layouts. Use named SDK constants and protocol enums rather than unexplained numbers. `windows-sys` is a build dependency only: `driver/build.rs` emits the named SDK constants into OUT_DIR, avoiding its raw-dylib user-mode WFP imports in the SYS. The host test crate uses the same generator. The build must verify the actual SYS import table against the kernel-only allowlist. `smoltcp` supplies stateless checksum/wire helpers with std/alloc/socket features disabled, not a second networking stack; enabling only its proto-ipv4 feature suffices for these family-independent helpers, while the existing Rust IPv6 parser/checksum logic remains intact.

Ownership on the NDIS path follows the **internal NDIS path**, not public guest direction:

| Input | While awaiting verdict | Allow | Drop/cancel/pause before forwarding |
|---|---|---|---|
| Send | Retain original NBL | Send lower; complete upper on lower completion | Complete upper |
| Receive without `RESOURCES` | Retain lower-owned original | Indicate upper; return lower on upper return | Return lower |
| Receive with `NDIS_RECEIVE_FLAGS_RESOURCES` | Synchronously deep-copy NB/MDL/data; never retain or modify the original chain | Indicate private NBL without `RESOURCES`; free locally on upper return | Free private copy locally |

Private receive NBLs have `SourceHandle=filter` and must never be returned to the lower driver. Delayed operations recompute IRQL flags rather than replaying callback flags. Pointer-bearing/opaque OOB metadata outside the supported copy profile is rejected, not shallow-copied. Ownership and checked arithmetic live in `driver/src/native_ndis.rs` and `native_packet.rs`. There is no fixed NB-per-NBL ceiling, per-resource-copy total limit, per-module copy-data budget, or global allocation budget. NBL contexts and receive copies grow without fixed quotas; empty NBLs/zero-length NBs remain invalid, non-allocation copy failures drop, and every partially constructed private chain must be freed exactly once.

Pause closes admission, explicitly invalidates existing pending IDs and all four caches for the interface index, drains queued originals/copies, and waits for forwarded sends and indicated receives. Do not originate packets after pause completes. **No NDIS send/indicate/complete/return calls under the Rust policy lock.** Regular OIDs are cloned/forwarded with rundown; direct-OID handlers are NULL so NDIS bypasses them. There is no switch topology/OOB dependency.

Permanent cache is **TCP/UDP only**. Each host `interface_index` owns four separate dynamically growing tables (TCP/IPv4, UDP/IPv4, TCP/IPv6, UDP/IPv6), with no fixed entry count or capacity eviction. Inside a table, hash and full identity are exclusively normalized local_ip + local_port + remote_ip + remote_port; interface_index, protocol and IP family select a table and are not hashed/stored in entries. There is no Scope/path/VLAN/module/generation equality guard: both directions and VLANs share a decision for identical normalized tuples within one interface/protocol/family table. TCP and UDP never share entries or refresh each other's TTL. Full tuple comparison resolves hash collisions. Non-TCP/UDP never seed or use cache entries. PermanentAccept uses sliding idle TTL on actual cache hits; PermanentBlock/PermanentDrop keep fixed TTL. Cache tables use SwissTable-style 16-byte SSE2 control groups on x64 (eight-byte scalar fallback for other host policy targets), seven-bit fingerprints, triangular group probing, and the benchmark-selected rotate/XOR/multiply word hash. Full equality remains mandatory; this deterministic hash is not keyed HashDoS protection. No std map, AVX or x87 is used in the kernel. Windows x64 compiler/ABI preserves baseline SSE state; no explicit extended-state save/restore is needed. The rationale/source is documented in policy/src/cache/group.rs. One allocation holds controls, a mirrored group, and aligned raw entry storage; only controls need initialization, and entries are fully written before publishing a fingerprint. Cache allocation/control initialization and retired-table free happen outside PolicyLock using a separate nonpaged allocator with no aggregate byte budget; checked size failures may prevent insertion. Growth/compaction is requested at 75% live/used load; a new insertion may shrink a table below one-eighth live load to one quarter of its capacity, no smaller than the initial size; migration is incremental (32 slots per insertion step), with no expiry sweep or rehash in the packet lookup hot path. Only insertion advances growth/compaction migration. Each cache cleanup run scans all candidate interfaces and current/previous tables of all four TCP/UDP IPv4/IPv6 caches using a fixed expiry cutoff; a PASSIVE_LEVEL system work item releases PolicyLock between ranges of at most 256 slots per table, without deferring ranges to later timer ticks. Timer/explicit requests coalesce and unload waits for worker rundown. Ordinary insertion does not sweep expiry. The previous linear implementation is frozen only in policy/examples/cache_lookup_bench/linear_cache.rs for offline comparisons and is never included by the driver library. Clear/session reset disables all banks; pause/invalidate/detach disables all four caches of the affected interface and reclaims them unlocked one bank at a time, avoiding large kernel-stack arrays. Attaching NDIS to an existing WFP interface index does not by itself reset its shared cache or pending state. WFP deliberately performs no interface connect/disconnect reset; its existing numeric-index cache state follows TTL, ClearCache and controller-session reset. At most one idle forward-only row without valid pending decisions or cache allocation is retained while online; it may be reassigned to another index and is released on disconnect. Publication re-establishes membership after unlocked capture. A per-index pending count is reset on invalidation, and invalidated claims never decrement a reused index.

Pending policy context identifies its observed interface **only by interface_index**; no adapter/module ID, epoch, path or VLAN is stored or checked when applying verdicts. Attached indices must be nonzero and unique; ambiguous duplicate attachments are rejected. Pause/invalidate/detach explicitly marks existing pending IDs for that interface invalid before draining them, so restart or reuse cannot revive old requests. There is no generation counter in Rust or the Rust native layer. The shim retains the original NBL owner and send/receive route only for correct NDIS ownership/completion; an optional send cancellation ID is interface-scoped and absent for receives. Diagnostic module_id remains snapshot-only, not a policy identifier. Keep NDIS ownership/cancellation separate from public direction; do not invert native-Rust `HV_DIRECTION_SEND`/`HV_DIRECTION_RECEIVE` constants. Cancel-send must not claim receive entries with the same numeric cancel ID. Each active send callback registers a stack-owned batch under the adapter lock, exposing its unprocessed NBL chain and the current classification's cancellation flag. Cancellation unlinks matching unprocessed sends and marks the current send while locked; policy completion and NDIS calls run after unlocking. Policy preflight and publication check that flag while holding PolicyLock followed by the adapter lock; cancellation must never enter policy while holding the adapter lock. A send whose immediate allow or pending verdict wins the race to ownership remains subject to NDIS best-effort cancellation, including during handoff to the lower driver. Mixed-flow/IP-non-IP batches and malformed packets are dropped; multi-NB IP batches processed by policy are allowed only for non-fragmented TCP/UDP packets whose flow keys are fully identified and match. Single-NB packets of other IP protocols still follow normal policy. Fragments/offloads/incomplete transport headers and multi-NB batches cannot seed or refresh permanent cache entries. Non-IP control frames bypass the L3 event API only when ownership is safe.

Default fallback is fail-closed (drop) for missing/disconnected controller, timeout, and policy/queue limits. Engine construction and the native-Rust missing/malformed `FailClosed` registry-value fallback both default to enabled (`1`); an explicit `FailClosed=0` still opts into fail-open. Online uncached IP packets selected for policy wait for a verdict until their deadline, then drop; no controller means immediate IP drop subject to self-injection and optional fragment-diagnostic exceptions. Valid cached allows still originate from userspace and work while online; disconnect/shutdown clears them. Non-IP control-frame bypass is unchanged. Ownership/parser/copy failures, unsupported copy metadata, and pause remain drop paths even with fail-open. Defaults: 8000 ms decision deadline and 60 s cache TTL. Separate driver timers check pending timeouts every 1 s only while pending NBLs exist and request a full expiry sweep every 10 s only while nonempty cache banks exist. Publish maintained pending and nonempty cache-bank counts in O(1); cleanup uses an interface-index cursor with an initial upper bound, not a fixed-width adapter bitmask; arm/cancel timers only on candidate transitions, never on every packet/hit. No unconditional 50 ms timer or monitor cleanup polling. Timeout fallback may lag the deadline by one check interval plus scheduling; verdict validation still uses the actual deadline. Migration remains insertion-only, not timer work. Service `Parameters` can override `DecisionTimeoutMs`, `CacheTtlMs`, and `FailClosed`; target configuration is separate.

### Binding isolation: installer, notify object, kernel gate

`install/HyperVXNdisFilter.inf` declares `FilterClass=custom`, `FilterType=2`, `FilterRunType=2`, `FilterMediaTypes=ethernet`; never `ms_switch_filter` or `vmnetextension`. The driver-store notify-object packaging requires **Windows x64 build 25341+**.

The current driver-store INF package and device API version are **0.3.3.0** (blocking reads and host adapter indices). Connection records include interface_index:u32 immediately after id:u64; each bandwidth group header carries interface_index:u32 after protocol:u8 and before count:u32, breaking compatibility with 0.3.2.0 and earlier event streams. Connection events no longer contain process_id and carry complete IP packets. The earlier 0.2.1.4 setup fixes (GetClassGuid/E_POINTER, non-PnP identity and disable-before-arm ordering) remain. Use a coherent new INF/DLL/CAT/setup EXE set and matching monitor, never older package pieces.

The isolation layers must stay consistent:

1. `install/console/Hns.cpp` performs a read-only native HNS request (`hns.1` Request2 GET /networks) and parses it with Windows JSON APIs. Select all records by **Type=ICS**, never names. ICS network IDs must be nonzero/unique; `SwitchGuid` supplies the authoritative switch association and need not equal network ID. Shared switch references are deduplicated. Empty/malformed/ambiguous ICS discovery fails closed; there is no mandatory Default Switch or WSL identity/fallback. Never start WSL or create/change HNS networks during discovery. `Target.cpp` resolves each HNS-proven switch through native Hyper-V WMI, follows internal management-OS port / LAN endpoint / active connection associations, and selects **all** connected host vNICs, matching each `DeviceID` GUID to the exact Ethernet virtual `MSFT_NetAdapter` GUID/LUID with a NETIO round-trip check. Several host ports on one ICS switch are supported. Discovery is sorted by GUID; complete set comparisons ignore enumeration order. `scripts/HyperVXNdisFilter.Common.ps1` retains equivalent type-based selection for the optional helper. Friendly names and hardcoded machine GUID/LUIDs never authorize adapters.
2. `dist/Install.exe` writes `HKLM\SOFTWARE\HyperVXNdisFilter\Lwf` with `ConfigVersion=3`, an atomic `TargetAdapters` REG_BINARY allowlist and **AllowBindings=0 durably before identity changes/NetCfg installation**. The blob is `[count:u32 LE]` followed by `[Windows GUID:16 bytes][NET_LUID:u64 LE]` per target. There is **no fixed target-count quota**, including no two-adapter cap; checked native u32 byte-length arithmetic applies. `driver/shim/target_config.h` rejects zero/duplicate identities, zero count, overflow and malformed lengths. Kernel staging is dynamically allocated nonpaged at PASSIVE_LEVEL before module allocation without NDIS/policy locks and freed on every exit; user-mode readers likewise allocate actual lengths, with bounded growth retries. Wire/API stays 0.3.3.0; schema-2 configurations still require explicit uninstall/reinstall. Setup rejects enabled foreign paths, durably disarms/disables automatically enabled exact-target paths, verifies all paths disabled, revalidates the complete ICS set, arms, then enables every exact configured target path. Unexpected enabled foreign paths cause abort/rollback of this component, never broad binding edits.
3. `install/notify/` is a separate user-mode COM DLL implementing `INetCfgComponentControl` and `INetCfgComponentNotifyBinding`. `QueryBindingPath` returns `NETCFG_S_DISABLE_QUERY` for this component's add/enable paths unless armed and resolving to exactly one configured GUID/LUID pair, verified against current NETIO identity. Disable/remove are allowed. Windows can automatically enable a non-PnP vNIC path with only NotifyBindingPath and no QueryBindingPath veto: never rely on the notify object alone. Building/testing the DLL never registers it.
4. Kernel `FilterAttach` independently checks `BaseMiniportNetLuid`, armed/versioned configuration, and GUID conversion using `ConvertInterfaceLuidToGuid` against the same validated binary allowlist. Missing/stale/old-schema config or conversion failure rejects attach before module allocation; never fall back to adapter name or broaden scope.

Binding traversal is shared in `install/notify/BindingPath.h`: NetService class + package NetCfgInstanceId proves filter ownership. Adapter classification uses the GUID inventory from class-scoped NetCfg enumeration merged with NETIO GetIfTable2 in `AdapterInventory.h`, with successful direct Net-class identity also supported. Dynamic non-PnP interfaces can be absent from EnumComponents(Net); adapter GetClassGuid can fail even on canonical enumerator objects. Never require GetId/display-name strings or authorize by parsing path tokens. Instance GUID errors/null/ambiguous paths and malformed inventories still fail closed. The package filter instance GUID is not a machine target GUID.

Do not substitute the unverified `DefaultFilterSettings` registry idea for these gates. Adapter recreation, adding/removing ICS targets or changing network type requires explicit uninstall/reinstall, not automatic retargeting. Never broaden a stored target list during `--enable` or optional helper use. NetCfg installation is system-wide and may cause Windows network reconfiguration even when foreign binding paths are vetoed.

`Set-Binding.ps1` explicitly enables/disables only the configured target bindings and revalidates the complete identity set after confirmation. `dist/Uninstall.exe` disarms and removes only component `hyperv_xndis_filter`, without requiring the target adapter to still exist. Both EXEs use native Windows APIs, never launch PowerShell or netcfg.exe, and require an already elevated admin/SYSTEM console for actions; `asInvoker` keeps help/invalid CLI offline-safe. The package defaults to the EXE directory, not the working directory. `--what-if` performs read-only preflight; `--yes` only skips confirmation. Fresh-install rollback removes only the component just installed; staged Driver Store packages are not forcibly purged. Do not replace an installed live SYS, force SCM creation/deletion, or bypass requested reboots. NetCfg installation/removal belongs to these native EXEs, not the removed `Install.ps1`/`Uninstall.ps1` scripts. The console monitor may create/delete only its own temporary WFP-only SCM service.

### Public API and userspace

The full public API is documented in [README.md](README.md#api). The C++ monitor/client in `monitor/` uses direct Windows device I/O only: no named-pipe/winrpc bridge, IPC server, external verdict owner, or dependency on the original Portmaster checkout. `monitor/include/PortmasterKext.h` defines the `pmkext` client API; `monitor/include/DriverProtocol.h` and `monitor/src/DriverProtocol.cpp` implement its bounded codec, corresponding to `protocol/src/lib.rs`. `install/notify/` is also built by `monitor/CMakeLists.txt`, but is not part of the kernel image.

Preserve these compatibility constraints:

- Events: `[type:u8][body_size:u32 LE][body]`, with a **5-byte header and 1048636-byte maximum complete connection record** (1 MiB payload + 60-byte IPv6 prefix; IPv4 prefix is 36 bytes). `body_size` excludes the header. All numeric fields, including ports, are little-endian; IP address bytes are network order. Never serialize native C++/Rust structs.
- Commands are unframed, fixed-size; a write is nonempty and fits the native Windows **DWORD/u32** length, without a driver-defined 64 KiB cap. Validate the **entire batch before applying any command**. Verdict is exactly ten bytes: `[1:u8][id:u64 LE][verdict:u8]`. This is syntactic validation, not a transaction/acknowledgement of live IDs.
- **ConnectionIpv4/ConnectionIpv6 contain no process_id; --filter-pid is unsupported. interface_index:u32 immediately follows id:u64 and identifies the host adapter (BaseMiniportIfIndex), not a guest interface. Keep it in each Rust Interface context and each native-Rust module; never use a global current interface index. For WFP use the actual source interface index. No compartment/sub-interface ID, TID or public switch/port/GUID/LUID fields.** Unused legacy END compatibility types retain PID=0. Pending/cancellation isolation uses the interface index and explicit pending-ID invalidation, not module IDs or epochs; interface lifecycle resets all four of its protocol/family caches.
- Direction **0 = guest outbound (host NDIS receive)**, **1 = guest inbound (host NDIS send)**. `local_*` is the guest endpoint and `remote_*` is the peer. Host-send normalization swaps endpoint descriptions, not captured packet bytes. Global IPFORWARD is always source-relative direction=0 with local=IP source, not guest attribution. Do not hardcode Sandbox IPs or infer direction from TCP connection initiator.
- Payload is the complete observed L3 IP packet, without Ethernet/VLAN headers or Ethernet padding, up to 1 MiB; never truncate an event to fit. Larger logical packets are dropped. One event/ID represents one owned NBL, not a socket; a homogeneous multi-NB NBL carries the full first NB packet, not every NB's payload. Non-IP traffic and cache hits do not generate verdict events. LSO/RSC payloads are logical NDIS packets, not necessarily wire segments.
- Small Packet/Connection/Pending metadata stays fixed-size. Pending decisions, events and interface contexts use stable-node lists (`policy/src/storage.rs`), not fixed item-count arrays or growing-array relocations under PolicyLock. Bandwidth aggregation uses stable 128-entry raw pages and an incremental open-addressing handle index (`policy/src/bandwidth.rs`); live counter entries never move, and prepared page/index ownership is transferred without large initialization or free under PolicyLock. Their small node allocations, native-Rust NBL contexts and full packet records (Vec allocations, including in-flight captures) have no aggregate byte budget; event queues also have no configured byte quota. Keep size/count arithmetic checked; actual nonpaged-pool exhaustion bugchecks on failed `ExAllocatePool2`. There is no fixed 256/512/32/2048-element quota. A queued event retains its pending node until the event leaves the queue and the NBL is claimed; partially read frames must finish even after timeout/cancellation. Unread claimed events unlink immediately in O(1). Session resets retire event and bandwidth chains for bulk destruction outside PolicyLock, using `take_retired_storage` and driver `reclaim_retired`; detached bandwidth reports retain unqueued banks and consolidate duplicate keys outside the lock. Successfully reported groups release sealed indexes; detached pages compact in place outside the lock, preserving unqueued deltas. A missing bandwidth resource is prepared unlocked and the accounting operation is retried synchronously, without repeating the packet decision or starting background work. Controller-session resets reject stale deferred accounting. Detached reports encode one group directly or count and encode multiple groups without sorting per-entry pointers; partial reports compact surviving entries outside PolicyLock. Never bulk-free an arbitrarily long list while locked. Bandwidth has no entry quota: its handle index grows at 75% load and only insertion scans up to 32 old slots per migration step; hits never advance migration. Copy directly into final event storage OUTSIDE the policy spin lock; enqueue writes only the small wire prefix. Never put a packet-sized array on the kernel stack. Malformed packets and unsupported NDIS copies still drop. Free record storage on full/stale reads and connect/disconnect.
- Accept=2, PermanentAccept=3, Block=4, PermanentBlock=5, Drop=6, PermanentDrop=7. **Redirect and UpdateV4/V6 are unsupported**, even though legacy enum names remain in the client header. Block/Drop silently discard without RST/ICMP. Permanent means a cacheable TCP/UDP tuple TTL entry, not socket lifetime permission; both directions share matching normalized tuples within one interface/protocol/family table, but TCP and UDP never share entries.
- The pending timeout starts at classification, not when userspace reads the event. Late/duplicate/unknown/cancelled IDs are successful no-ops and never seed cache entries. There is **no per-verdict acknowledgement**; a successful write does not prove an NBL was still pending.
- No synthetic connection-END events: NDIS has no ALE/socket lifecycle. Compatibility types/callbacks remain, but the driver never emits event types 3/4. `CleanEndedConnections` only expires cache entries; `ClearCache` invalidates cached decisions without answering pending packets.
- Bandwidth measures **admitted TCP/UDP IP bytes while the controller is online**, by host `interface_index` plus normalized guest/peer tuple: NDIS TX guest outbound/RX guest inbound; WFP TX is source-interface-relative with local=IP source. These are deltas since creation/last successfully queued report, not cumulative socket totals or delivery confirmation. `GetBandwidthStats` emits the entire group for each `(interface_index, protocol, IPv4/IPv6)` in one record (types 5/6), without an artificial entry-count or frame-size cap and without splitting. Body header is `[protocol:u8][interface_index:u32][count:u32]`; all following entries share the index. Entries are 28/52 bytes: each address immediately followed by its port, then TX/RX u64. Only checked `body_size:u32`/`count:u32` and actual allocation bound a group; the 1 MiB connection payload and 512-byte log limits are unchanged. Unqueued groups keep every delta. Internal aggregate-NBL byte counts and TX/RX counters remain saturating 64-bit.
- `GetLogs` is a compatibility no-op because logs are already queued. `PrintMemoryStats` queues an Info `LogLine`, not a new event type. Traffic diagnostic counters are collected only while the controller is online and reset on disconnect. Diagnostic/statistics requests have no correlation ID and need not produce a record when no data exists or allocation fails.
- `--match` selects the **remote endpoint in both directions**; unmatched events receive PermanentAccept. `--filter-ip` only hides output and does **not** narrow verdict scope. Without `--match`, an explicit verdict applies to every event and can cut host-vNIC connectivity.

### Header-only client

`monitor/include/HyperVXNdisFilter.hpp` is an independent C++20 Windows x64 header in namespace `hypervxndisfilter`, with `Client` and a single caller-owned blocking Run thread. ConnectionV4/V6 callbacks borrow packed fixed-header/payload pointers; BandwidthV4/V6 callbacks borrow an entire packed entry array once per nonempty record. Scoped packing and size/alignment/offset assertions describe the explicit wire layout; do not rebuild normalized event structures or take aligned integer references to packed fields. These pointer callbacks replace the old unified Connection/Bandwidth callbacks in this header only; both clients require wire version 0.3.3.0 and expose the host interface index in connection and bandwidth records; packed ConnectionV4/V6 headers are 27/51 bytes and BandwidthV4/V6 entries are 28/52 bytes; their shared interface_index:u32 is passed as a separate callback argument after protocol. It never installs a driver. `Open()` returns `ERROR_SHARING_VIOLATION` immediately on any device-open attempt; releasing another controller is not a startup signal. On other open failures, it waits indefinitely on protected `Global\HyperVXNdisFilter.DriverReady` (reset before retry, no startup timeout/device polling); Stop cancels the wait. A Stop requested while closed cancels the next Open once before device access; a successful Close clears a pending stop. A Run duration bounds monitoring only, not startup. Stop is local, Shutdown also issues the IOCTL, Close requires Run/all callers joined. No automatic statistics timer/verdicts or per-entry allocation/copy; receive storage can grow fallibly for large bandwidth groups; head/tail cursors defer partial-frame compaction until writable space is short. Header-only build/example/tests must not link pmkext. Advapi32 is a system dependency (MSVC pragma). Tests fake device APIs and the named readiness event with private unnamed objects, never the production device/global event. `callback_client.exe` is a live example, not an offline test.

### Device session and C++ threading

- Device `\\.\HyperVXNdisFilter`: Administrator/SYSTEM, exclusive read/write controller. `IOCTL_VERSION` uses function `0x800` / code `0x9C40E000` and returns exactly `00 03 03 00` (**0.3.3.0**). `IOCTL_SHUTDOWN` uses function `0x801` / code `0x9C40E004`. `IOCTL_FILTERED_DEVICE_COUNT` uses function `0x802` / code `0x9C40E008` and returns exactly four little-endian bytes (`u32`): the atomic count of running NDIS modules, updated with the adapter admission gate on successful restart and pause start, not configured/enabled bindings or observed traffic. Session shutdown does not reset it. All are buffered, require read/write access, and take no input; the count query rejects nonempty input and output buffers smaller than four bytes. The additional adapter snapshot IOCTL is described next; no other IOCTL is supported. `Driver::GetFilteredDeviceCount` leaves its output unchanged on failure; the monitor prints the count at startup and on changes at `--poll` intervals, respecting `--out`/`--timestamps`. Unsupported/failed queries warn once per failure streak without inventing zero or stopping packet monitoring. This additive IOCTL does not change the 0.3.3.0 event wire layout. Package/Cargo versions are separate; the monitor rejects older wire versions.
- `IOCTL_ADAPTER_INFO` uses function `0x803` / code `0x9C40E00C`, empty input, buffered read/write access, and a versioned attached-module snapshot including not-running modules. Header: four LE u32 values `(schema=1, entry_size=1760, count, running_count)`; exact successful total `16 + count * 1760`. There is no 32-adapter quota: only checked 32-bit IOCTL byte-length arithmetic bounds the count. An undersized output that holds the header gets exactly 16 bytes with `STATUS_BUFFER_OVERFLOW`/`ERROR_MORE_DATA`; outputs below 16 bytes get `STATUS_BUFFER_TOO_SMALL`. Both clients initially allocate 56336 bytes for compatibility with older schema-1 SYS builds and grow fallibly on valid sizing headers, using bounded retries for topology churn; never allocate the arithmetic maximum upfront. `driver/src/adapter_info.rs` owns the portable explicit codec/size planner and UTF-16 handling; `driver/shim/adapter_info.h` retains the asserted internal storage/FFI declarations. The diagnostic list lock protects detach lifetime, metadata and running-count consistency while copying into nonpaged staging storage; allocation, explicit wire encoding and frees happen unlocked. Header-only sizing replies allocate no staging. Bounded internal retries handle growth while staging is allocated; exhaustion returns `STATUS_RETRY`, not a bogus empty/partial snapshot. Never take an adapter/policy lock or call NDIS while holding the diagnostic lock. Identity/names/MAC come from attach, general attributes from successful restart, link values from valid link-state indications. Missing optional values have validity flags; names are at most 255 UTF-16 code units plus NUL with explicit truncation flags. Both C++ clients expose owning `AdapterInfo`/`AdapterSnapshot` and `GetAdapterInfo`, leaving output unchanged on failure. Monitor prints once at startup with `--out`/`--timestamps`; unavailable queries warn without stopping monitoring. Event version remains 0.3.3.0; do not infer snapshot availability from that version alone. No OID queries, binding changes, kernel pointers or guest ownership are added.
- `Driver::Open` opens the existing device with `FILE_FLAG_OVERLAPPED`; it does **not** wait for startup or check the version. Integrations must call `GetVersion`, as the monitor does. The constructor's `service_name` selects only the device basename. `Driver::Install` is an unsupported compatibility stub; keep SCM loading in the separate console-only `DriverLoader`, not the reusable pmkext/header-only clients. `Driver::Open` preserves its Win32 failure code in `GetLastError`.
- Console startup first tries the device, then one temporary SCM load if the device is absent; failures return an error rather than waiting indefinitely. Without `--duration`, the session runs until Ctrl+C. A positive duration bounds monitoring, not synchronous SCM initialization. `driver/src/native_device.rs` uses secure WDM control-device creation only for exact service `Parameters\StandaloneWfp=1`; missing/malformed values keep ordinary NDIS+WFP initialization. Both modes use the same protected Admin/SYSTEM ACL, wire/API and rundown. The header-only client's readiness-event startup wait remains unchanged.
- `driver/shim/driver_ready.h` shares Win32 and `\BaseNamedObjects\HyperVXNdisFilter.DriverReady` kernel names. The Rust native layer signals only after the device/timer are initialized, retains the event object/handle, then clears/closes it on unload. Event creation is best-effort (the global directory may not exist during early boot); do not fail LWF initialization for a notification failure. Rebuilt monitor alone cannot add startup signaling to an older installed SYS. Offline startup tests use fake openers/private Local test events, never the production global object.
- Opening activates a policy session and clears its event queue/cache/bandwidth. Shutdown or handle cleanup deactivates it, clears those queues, and resolves pending packets through fallback (invalidated paths still drop). To activate again after shutdown, close and reopen; shutdown neither closes the handle nor unloads/unbinds the filter.
- Nonzero reads wait for bytes in a cancel-safe queue, with no fixed waiting-IRP count or byte budget. Reads/writes have no driver-defined 65536-byte cap, only native Windows DWORD/u32 length bounds; writes remain nonempty and fully validated before side effects. One completion can coalesce records beyond 64 KiB; release PolicyLock between short internal copy chunks rather than holding it over an arbitrarily large read. Reads never succeed empty just because the queue is empty. Explicit zero-length reads still return zero. Shutdown/cleanup/unload cancel pending reads; clients must cancel/reap before releasing OVERLAPPED storage. `driver/src/native_device.rs` owns the CSQ/work item, IRP+worker rundown and client gate. Rust with_state publishes queue readiness/online state while policy-locked; only work scheduling occurs there, never NDIS calls or IRP completion. There is no idle read polling. Reads can split/coalesce records. Client 65536-byte streaming buffers are a buffer choice, not a device limit. `RecordStream` buffers one frame and grows storage fallibly for complete bandwidth groups; connection frames retain the 1048636-byte bound and log records the 512-byte bound. Invalid headers invalidate the stream until `Reset`, with no guessed resynchronization.
- `Run` starts a reader thread but blocks the caller. Event handlers run on the reader; `on_poll` runs on the calling thread; `on_warning` may run on either. Callback data is temporary. Synchronize shared state, keep handlers short, and explicitly request statistics/send verdicts; `Run` does not do these automatically.
- `RequestShutdown` only issues the IOCTL; it does not signal the `Run` stop event. `Stop` signals that event and sends shutdown once, and is safe during `Run`. Wait for `Run` to return/join before `Cleanup` or destruction; neither operation manages the installed LWF. Authorized custom clients also need a bounded runtime deadline.
