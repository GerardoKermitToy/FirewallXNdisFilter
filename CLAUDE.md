This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Scope and operating constraints

FirewallXNdisFilter 0.3.3 is an experimental **ordinary NDIS 6.40-6.89 optional modifying Ethernet Lightweight Filter (LWF)** for compatible host Ethernet adapters, physical or virtual. It is **not a Hyper-V switch extension** and does not use WFP; do not restore WFP callouts or use `Enable-VMSwitchExtension`. NDIS cannot attach this ordinary filter to every interface: in particular Wintun/WireGuard adapters declaring `LowerRange=nolower` are outside its scope.

- Work in the separate `C:\hyperv` repository. `C:\portmaster_v3` is the compatibility/reference project, not a build dependency; do not modify it as part of FirewallXNdisFilter work.
- **Create commits only when explicitly requested.** The working branch is `master`; inspect the current branch/status before Git mutations. Amend the last commit only when explicitly requested, and do not infer permission to push or force-push from permission to commit/amend.
- **Build the kernel driver in release mode only.**
- The user authorizes agent-run driver installation/loading/binding, native setup notify registration, device access, and live traffic tests using `192.168.219.15`; a separate request for each such test is not required. Use native Install.exe/Uninstall.exe and retain recovery/cleanup evidence. Offline builds and tests do not require installation.
- Network configuration changes needed for this work are permitted, including HNS/ICS/NAT, switches, VM placement, IP/routes, and adapter bindings. Inspect and record the affected state first, preserve unrelated connectivity, and restore temporary diagnostic changes. Do not change certificate stores, boot/security policy, or Driver Verifier without separate explicit authorization.
- `ndis_monitor.exe` opens the existing device only. It does not install, start, bind or stop a driver, create a temporary service, or accept a SYS path. Agent-run monitor sessions may omit `--duration` if tracked and cleaned up; `--help` is offline-safe. Full NDIS installation/removal belongs to the native setup EXEs.

This filter sees only traffic traversing an attached **host Ethernet adapter send/receive path**, not necessarily VM-to-VM traffic inside a switch. Public direction 0 is host receive, direction 1 is host send; guest attribution is meaningful only on an appropriate guest-facing adapter. Neither direction nor endpoints establish process or VM ownership.

## Architecture and invariants

### Kernel data path: Rust owns policy and the native WDK boundary

The complete kernel, including native WDK callbacks and NBL/NB/MDL/IRP operations, is Rust. User-mode setup/notify/monitor remain C++. `driver/build.rs` uses windows-drivers-rs `wdk-build` and build-only bindgen/libclang against the installed WDK; do not hand-maintain WDK layouts. Rust uses the `no_std`-compatible `likely_stable` crate. Hints favor IPv4 TCP/UDP and allocation success, not a particular TCP/UDP split, verdict, cache-hit rate or offload profile. Keep input checks and ownership cleanup. A failed `ExAllocatePool2` must bugcheck; other allocation APIs are assumed to succeed without OOM checks. Never replace a hint with `__assume` or unreachable error paths.

`driver/src/native_ndis.rs`, `native_device.rs`, `native_registry.rs`, `native_packet.rs`, and `native.rs` are the Rust WDK ABI boundary: NDIS registration/callbacks, target attach gate, device I/O, locks/timer, NBL-local ownership contexts and copy pools, OIDs, and pause/restart/detach. It calls the `Fwx*` exports in `driver/src/lib.rs`, which bridge to the Rust policy engine. The Rust driver is a `no_std` static library; `cargo build` alone does **not** produce the final `.sys`. The kernel image is `FirewallXNdisFilter.sys`, with matching `FirewallXNdisFilter.pdb`. The complete product rename also uses `FirewallXNdisFilter.inf`, `FirewallXNdisFilter.cat`, `FirewallXNdisFilterNotify.dll`, service/device `FirewallXNdisFilter`, startup event `Global\FirewallXNdisFilter.DriverReady`, NetCfg component `firewallx_ndis_filter`, and header `FirewallXNdisFilter.hpp` / namespace `firewallxndisfilter`. Setup/notify C++ uses namespace `firewallx_ndis_filter`; environment variables use prefix `FIREWALLXNDISFILTER_`. There are no old-name aliases. Wire/API version remains 0.3.3.0, and package/notify GUIDs remain unchanged. Start a rename rebuild with a clean dist; do not mix package generations. The installer detects a previous-name component by the stable filter GUID and refuses it. Remove a prior installation only with its matching old tools, explicitly authorized; never rename or replace an installed SYS. Raw historical logs and signed backups are evidence, not current build inputs; do not rewrite them to claim renamed-package validation.

`policy/src/packet.rs` parses bounded Ethernet/VLAN/IPv4/IPv6/TCP/UDP data and normalizes guest/peer endpoints. Its internal `NdisPath` decodes native-Rust values (0=Send, 1=Receive) and maps them to the opposite public guest direction (Send=Inbound, Receive=Outbound). `policy/src/engine.rs` manages pending decisions, event streams, per-interface TCP/UDP IPv4/IPv6 tuple TTL caches, and bandwidth aggregation. `protocol/src/lib.rs` owns explicit byte encoding and command validation; never serialize native C/Rust struct layout onto the wire.

The driver is NDIS-only; it must not register WFP callouts or injection handles. Normally only IP packets whose source and destination are not local adapter addresses are eligible for policy. Address inventory and reconciliation must run outside packet-path locks; a dirty or unavailable inventory must not be treated as proof that an address is nonlocal. Observe only traffic traversing attached compatible Ethernet adapters. No packet deduplication is guaranteed across interfaces. After validating every NB, the driver warns once and splits a mixed local/transit NBL into per-NB children. Local children bypass policy; transit children receive independent policy decisions and bandwidth accounting without cache lookups or insertions. Unsupported metadata and NBL flags remain drop paths.

NDIS uses one Engine and common pending/event/cache/bandwidth structures. The API verdict ID directly selects one Pending containing the actual owned NBL address, not a separate opaque token. NDIS ownership metadata is attached using NdisAllocateNetBufferListContext and removed before returning/freeing it. Once pending ownership is published, the classifier never dereferences that NBL again; early verdicts finish through the normal completion path. The packet context has no policy/connection identity. NDIS completion/return validates its own context and module, preserving original/copy ownership and inline-completion safety. Policy finish and NDIS calls occur outside policy/classification locks. Offline native suites in `monitor/tests/native_rust` compile production NDIS/device/packet Rust modules against actual generated WDK layouts with fake OS calls. Never retain a duplicate C++ implementation or fake WDK layouts. Use named SDK constants and protocol enums rather than unexplained numbers. The build must verify the actual SYS import table against the kernel-only allowlist.

Ownership on the NDIS path follows the **internal NDIS path**, not public guest direction:

| Input | While awaiting verdict | Allow | Drop/cancel/pause before forwarding |
|---|---|---|---|
| Send | Retain original NBL | Send lower; complete upper on lower completion | Complete upper |
| Receive without `RESOURCES` | Retain lower-owned original | Indicate upper; return lower on upper return | Return lower |
| Receive with `NDIS_RECEIVE_FLAGS_RESOURCES` | Synchronously deep-copy NB/MDL/data; never retain or modify the original chain | Indicate private NBL without `RESOURCES`; free locally on upper return | Free private copy locally |

Private receive NBLs and split children have `SourceHandle=filter` and must never be returned to the lower driver. Split children use cloned NB/MDL descriptors referencing the original packet bytes; the original stays private and its NB chain stays unchanged until all children finish. The cloned NB order is restored before freeing its NDIS clone. A receive indicated with `RESOURCES` first deep-copies the original, which becomes the private split parent. The builder retains a reference across inline completions and early verdicts. Delayed operations recompute IRQL flags rather than replaying callback flags. Pointer-bearing/opaque OOB metadata outside the supported copy profile is rejected, not shallow-copied. Ownership and checked arithmetic live in `driver/src/native_ndis.rs` and `native_packet.rs`. There is no fixed NB-per-NBL ceiling, per-resource-copy total limit, per-module copy-data budget, or global allocation budget. NBL contexts and receive copies grow without fixed quotas; empty NBLs/zero-length NBs remain invalid, non-allocation copy failures drop, and every partially constructed private chain must be freed exactly once.

Pause closes admission, explicitly invalidates existing pending IDs and all four caches for the interface index, drains queued originals/copies, and waits for forwarded sends and indicated receives. Do not originate packets after pause completes. On failed local send admission, cancellation takes precedence; otherwise use `NDIS_STATUS_PAUSED` for a stopped module and `NDIS_STATUS_RESOURCES` for a creation/copy failure. Convert locally completed TCP LSO metadata to completion form even on failed admission; malformed LSO metadata must not override the cancellation or pause status. Paused drops count toward received/dropped totals but do not increment the resource-overflow counter. **No NDIS send/indicate/complete/return calls under the Rust policy lock.** Regular OIDs are cloned/forwarded with rundown; direct-OID handlers are NULL so NDIS bypasses them. There is no switch topology/OOB dependency.

Permanent cache is **TCP/UDP only**. Each host `interface_index` owns four separate dynamically growing tables (TCP/IPv4, UDP/IPv4, TCP/IPv6, UDP/IPv6), with no fixed entry count or capacity eviction. Inside a table, hash and full identity are exclusively normalized local_ip + local_port + remote_ip + remote_port; interface_index, protocol and IP family select a table and are not hashed/stored in entries. There is no Scope/path/VLAN/module/generation equality guard: both directions and VLANs share a decision for identical normalized tuples within one interface/protocol/family table. TCP and UDP never share entries or refresh each other's TTL. Full tuple comparison resolves hash collisions. Non-TCP/UDP never seed or use cache entries. PermanentAccept uses sliding idle TTL on actual cache hits; PermanentBlock/PermanentDrop keep fixed TTL. Cache tables use SwissTable-style 16-byte SSE2 control groups on x64 (eight-byte scalar fallback for other host policy targets), seven-bit fingerprints, triangular group probing, and the benchmark-selected rotate/XOR/multiply word hash. Full equality remains mandatory; this deterministic hash is not keyed HashDoS protection. No std map, AVX or x87 is used in the kernel. Windows x64 compiler/ABI preserves baseline SSE state; no explicit extended-state save/restore is needed. The rationale/source is documented in policy/src/cache/group.rs. One allocation holds controls, a mirrored group, and aligned raw entry storage; only controls need initialization, and entries are fully written before publishing a fingerprint. Cache allocation/control initialization and retired-table free happen outside PolicyLock using a separate nonpaged allocator with no aggregate byte budget; checked size failures may prevent insertion. If retirement or expiry invalidates storage prepared for a permanent verdict, leave the NBL pending and retry after unlocked reclamation/preparation, rechecking the ID, session and deadline before applying the decision. Growth/compaction is requested at 75% live/used load; a new insertion may shrink a table below one-eighth live load to one quarter of its capacity, no smaller than the initial size; migration is incremental (32 slots per insertion step), with no expiry sweep or rehash in the packet lookup hot path. Only insertion advances growth/compaction migration. Each cache cleanup run scans all candidate interfaces and current/previous tables of all four TCP/UDP IPv4/IPv6 caches using a fixed expiry cutoff; a PASSIVE_LEVEL system work item releases PolicyLock between ranges of at most 256 slots per table, without deferring ranges to later timer ticks. Timer requests coalesce and unload waits for worker rundown. Ordinary insertion does not sweep expiry. The previous linear implementation is frozen only in policy/examples/cache_lookup_bench/linear_cache.rs for offline comparisons and is never included by the driver library. Clear/session reset disables all banks; pause/invalidate/detach disables all four caches of the affected interface and reclaims them unlocked one bank at a time, avoiding large kernel-stack arrays. Publication re-establishes membership after unlocked capture. A per-index pending count is reset on invalidation, and invalidated claims never decrement a reused index.

Pending policy context identifies its observed interface **only by interface_index**; no adapter/module ID, epoch, path or VLAN is stored or checked when applying verdicts. Attached indices must be nonzero and unique; ambiguous duplicate attachments are rejected. Pause/invalidate/detach explicitly marks existing pending IDs for that interface invalid before draining them, so restart or reuse cannot revive old requests. There is no generation counter in Rust or the Rust native layer. The shim retains the original NBL owner and send/receive route only for correct NDIS ownership/completion; an optional send cancellation ID is interface-scoped and absent for receives. Diagnostic module_id remains snapshot-only, not a policy identifier. Keep NDIS ownership/cancellation separate from public direction; do not invert native-Rust `FWX_DIRECTION_SEND`/`FWX_DIRECTION_RECEIVE` constants. Cancel-send must not claim receive entries with the same numeric cancel ID. Each active send callback registers a stack-owned batch under the adapter lock, exposing its unprocessed NBL chain and the current classification's cancellation flag. Cancellation unlinks matching unprocessed sends and marks the current send while locked; policy completion and NDIS calls run after unlocking. Policy preflight and publication check that flag while holding PolicyLock followed by the adapter lock; cancellation must never enter policy while holding the adapter lock. A send whose immediate allow or pending verdict wins the race to ownership remains subject to NDIS best-effort cancellation, including during handoff to the lower driver. Incompatible transit-only flows, IP/non-IP batches and malformed packets are dropped; multi-NB IP batches processed by policy are allowed only for non-fragmented TCP/UDP packets whose flow keys are fully identified and match. Single-NB packets of other IP protocols still follow normal policy. Fragments/offloads/incomplete transport headers and multi-NB batches cannot seed or refresh permanent cache entries. Non-IP control frames bypass the L3 event API only when ownership is safe.

Default fallback is fail-closed (drop) for missing/disconnected controller, timeout, and policy/queue limits. Engine construction and the native-Rust missing/malformed `FailClosed` registry-value fallback both default to enabled (`1`); an explicit `FailClosed=0` still opts into fail-open. Online uncached IP packets selected for policy wait for a verdict until their deadline, then drop; no controller means immediate eligible-transit IP drop; local-address exemptions and unavailable-address-inventory bypass remain independent of controller state. Valid cached allows still originate from userspace and work while online; disconnect/shutdown clears them. Non-IP control-frame bypass is unchanged. Ownership/parser/copy failures, unsupported copy metadata, and pause remain drop paths even with fail-open. Defaults: 8000 ms decision deadline and 60 s cache TTL. Separate driver timers check pending timeouts every 1 s only while pending NBLs exist and request a full expiry sweep every 10 s only while nonempty cache banks exist. Publish maintained pending and nonempty cache-bank counts in O(1); cleanup uses an interface-index cursor with an initial upper bound, not a fixed-width adapter bitmask; arm/cancel timers only on candidate transitions, never on every packet/hit. No unconditional 50 ms timer or monitor cleanup polling. Timeout fallback may lag the deadline by one check interval plus scheduling; verdict validation still uses the actual deadline. Migration remains insertion-only, not timer work. Service `Parameters` can override `DecisionTimeoutMs`, `CacheTtlMs`, and `FailClosed`; target configuration is separate.

### Public API and userspace

The full public API is documented in [README.md](README.md#api). The C++ monitor/client in `monitor/` uses direct Windows device I/O only: no named-pipe/winrpc bridge, IPC server, external verdict owner, or dependency on the original Portmaster checkout. `monitor/include/PortmasterKext.h` defines the `pmkext` client API; `monitor/include/DriverProtocol.h` and `monitor/src/DriverProtocol.cpp` implement its bounded codec, corresponding to `protocol/src/lib.rs`. `install/notify/` is also built by `monitor/CMakeLists.txt`, but is not part of the kernel image.

Preserve these compatibility constraints:

- Events: `[type:u8][body_size:u32 LE][body]`, with a **5-byte header and 1048636-byte maximum complete connection record** (1 MiB payload + 60-byte IPv6 prefix; IPv4 prefix is 36 bytes). `body_size` excludes the header. All numeric fields, including ports, are little-endian; IP address bytes are network order. Never serialize native C++/Rust structs.
- Commands are unframed, fixed-size; a write is nonempty and fits the native Windows **DWORD/u32** length, without a driver-defined 64 KiB cap. Validate the **entire batch before applying any command**. Verdict is exactly ten bytes: `[1:u8][id:u64 LE][verdict:u8]`. This is syntactic validation, not a transaction/acknowledgement of live IDs.
- **ConnectionIpv4/ConnectionIpv6 contain no process_id; --filter-pid is unsupported. interface_index:u32 immediately follows id:u64 and identifies the host adapter (BaseMiniportIfIndex), not a guest interface. Keep it in each Rust Interface context and each native-Rust module; never use a global current interface index. No compartment/sub-interface ID, TID or public switch/port/GUID/LUID fields.** Unused legacy END compatibility types retain PID=0. Pending/cancellation isolation uses the interface index and explicit pending-ID invalidation, not module IDs or epochs; interface lifecycle resets all four of its protocol/family caches.
- Direction **0 = host NDIS receive**, **1 = host NDIS send**. `local_*` is source on receive and destination on send; `remote_*` is the opposite. This is guest-relative only on an appropriate guest-facing adapter. Host-send normalization swaps endpoint descriptions, not captured packet bytes. Do not hardcode Sandbox IPs or infer process/guest identity or connection initiator.
- Payload is the complete observed L3 IP packet, without Ethernet/VLAN headers or Ethernet padding, up to 1 MiB; never truncate an event to fit. Larger logical packets are dropped. One event/ID represents one owned NBL, not a socket; a mixed original yields independent per-NB children, and a homogeneous multi-NB NBL carries the full first NB packet, not every NB's payload. Non-IP traffic and cache hits do not generate verdict events. LSO/RSC payloads are logical NDIS packets, not necessarily wire segments.
- Small Packet/Connection/Pending metadata stays fixed-size. Pending decisions, events and interface contexts use stable-node lists (`policy/src/storage.rs`), not fixed item-count arrays or growing-array relocations under PolicyLock. Bandwidth aggregation uses stable 128-entry raw pages and an incremental open-addressing handle index (`policy/src/bandwidth.rs`); live counter entries never move, and prepared page/index ownership is transferred without large initialization or free under PolicyLock. Their small node allocations, native-Rust NBL contexts and full packet records (Vec allocations, including in-flight captures) have no aggregate byte budget; event queues also have no configured byte quota. Keep size/count arithmetic checked; actual nonpaged-pool exhaustion bugchecks on failed `ExAllocatePool2`. There is no fixed 256/512/32/2048-element quota. A queued event retains its pending node until the event leaves the queue and the NBL is claimed; partially read frames must finish even after timeout/cancellation. Unread claimed events unlink immediately in O(1). Session resets retire event and bandwidth chains for bulk destruction outside PolicyLock, using `take_retired_storage` and driver `reclaim_retired`; detached bandwidth reports retain unqueued banks and consolidate duplicate keys outside the lock. Successfully reported groups release sealed indexes; detached pages compact in place outside the lock, preserving unqueued deltas. A missing bandwidth resource is prepared unlocked and the accounting operation is retried synchronously, without repeating the packet decision or starting background work. Controller-session resets reject stale deferred accounting. Detached reports encode one group directly or count and encode multiple groups without sorting per-entry pointers; partial reports compact surviving entries outside PolicyLock. Never bulk-free an arbitrarily long list while locked. Bandwidth has no entry quota: its handle index grows at 75% load and only insertion scans up to 32 old slots per migration step; hits never advance migration. Copy directly into final event storage OUTSIDE the policy spin lock; enqueue writes only the small wire prefix. Never put a packet-sized array on the kernel stack. Malformed packets and unsupported NDIS copies still drop. Free record storage on full/stale reads and connect/disconnect.
- Accept=2, PermanentAccept=3, Block=4, PermanentBlock=5, Drop=6, PermanentDrop=7. **Redirect and UpdateV4/V6 are unsupported**, even though legacy enum names remain in the client header. Block/Drop silently discard without RST/ICMP. Permanent means a cacheable TCP/UDP tuple TTL entry, not socket lifetime permission; both directions share matching normalized tuples within one interface/protocol/family table, but TCP and UDP never share entries.
- The pending timeout starts at classification, not when userspace reads the event. Late/duplicate/unknown/cancelled IDs are successful no-ops and never seed cache entries. There is **no per-verdict acknowledgement**; a successful write does not prove an NBL was still pending.
- No synthetic connection-END events: NDIS has no ALE/socket lifecycle. Compatibility types/callbacks remain, but the driver never emits event types 3/4. Cache expiry cleanup is automatic; the former `CleanEndedConnections` command byte 8 is unsupported. `ClearCache` invalidates cached decisions without answering pending packets.
- Bandwidth measures **admitted TCP/UDP IP bytes while the controller is online**, by host `interface_index` plus normalized guest/peer tuple: TX is host receive and RX is host send; guest-relative descriptions apply only on appropriate adapters. These are deltas since creation/last successfully queued report, not cumulative socket totals or delivery confirmation. `GetBandwidthStats` emits the entire group for each `(interface_index, protocol, IPv4/IPv6)` in one record (types 5/6), without an artificial entry-count or frame-size cap and without splitting. Body header is `[protocol:u8][interface_index:u32][count:u32]`; all following entries share the index. Entries are 28/52 bytes: each address immediately followed by its port, then TX/RX u64. Only checked `body_size:u32`/`count:u32` and actual allocation bound a group; the 1 MiB connection payload and 512-byte log limits are unchanged. Unqueued groups keep every delta. Internal aggregate-NBL byte counts and TX/RX counters remain saturating 64-bit.
- `GetLogs` is a compatibility no-op because logs are already queued. At most 1000 queued `LogLine` records of any severity, including a partially read record, are retained; adding another evicts the oldest completely unread LogLine in O(1), without evicting connection or bandwidth events. A partially read frame must finish, and session reset clears the log index along with the queue. A verdict timeout increments the timeout counter and applies fallback without generating a LogLine. `PrintMemoryStats` queues an Info `LogLine`, not a new event type, and is subject to the same limit. Traffic diagnostic counters are collected only while the controller is online and reset on disconnect. Diagnostic/statistics requests have no correlation ID and need not produce a record when no data exists or allocation fails.
- `--match` selects the **remote endpoint in both directions**; unmatched events receive PermanentAccept. `--filter-ip` only hides output and does **not** narrow verdict scope. Without `--match`, an explicit verdict applies to every event and can cut host-vNIC connectivity.

### Header-only client

`monitor/include/FirewallXNdisFilter.hpp` is an independent C++20 Windows x64 header in namespace `firewallxndisfilter`, with `Client` and a single caller-owned blocking Run thread. ConnectionV4/V6 callbacks borrow packed fixed-header/payload pointers; BandwidthV4/V6 callbacks borrow an entire packed entry array once per nonempty record. Scoped packing and size/alignment/offset assertions describe the explicit wire layout; do not rebuild normalized event structures or take aligned integer references to packed fields. These pointer callbacks replace the old unified Connection/Bandwidth callbacks in this header only; both clients require wire version 0.3.3.0 and expose the host interface index in connection and bandwidth records; packed ConnectionV4/V6 headers are 27/51 bytes and BandwidthV4/V6 entries are 28/52 bytes; their shared interface_index:u32 is passed as a separate callback argument after protocol. It never installs a driver. `Open()` returns `ERROR_SHARING_VIOLATION` immediately on any device-open attempt; releasing another controller is not a startup signal. On other open failures, it waits indefinitely on protected `Global\FirewallXNdisFilter.DriverReady` (reset before retry, no startup timeout/device polling); Stop cancels the wait. A Stop requested while closed cancels the next Open once before device access; a successful Close clears a pending stop. A Run duration bounds monitoring only, not startup. Stop is local, Shutdown also issues the IOCTL, Close requires Run/all callers joined. No automatic statistics timer/verdicts or per-entry allocation/copy; receive storage can grow fallibly for large bandwidth groups; head/tail cursors defer partial-frame compaction until writable space is short. Header-only build/example/tests must not link pmkext. Advapi32 is a system dependency (MSVC pragma). Tests fake device APIs and the named readiness event with private unnamed objects, never the production device/global event. `callback_client.exe` is a live example, not an offline test.

### Device session and C++ threading

- Device `\\.\FirewallXNdisFilter`: Administrator/SYSTEM, exclusive read/write controller. `IOCTL_VERSION` uses function `0x800` / code `0x9C40E000` and returns exactly `00 03 03 00` (**0.3.3.0**). `IOCTL_SHUTDOWN` uses function `0x801` / code `0x9C40E004`. `IOCTL_FILTERED_DEVICE_COUNT` uses function `0x802` / code `0x9C40E008` and returns exactly four little-endian bytes (`u32`): the atomic count of running NDIS modules, updated with the adapter admission gate on successful restart and pause start, not configured/enabled bindings or observed traffic. Session shutdown does not reset it. All are buffered, require read/write access, and take no input; the count query rejects nonempty input and output buffers smaller than four bytes. The additional adapter snapshot IOCTL is described next; no other IOCTL is supported. `Driver::GetFilteredDeviceCount` leaves its output unchanged on failure; the monitor prints the count at startup and on changes at `--poll` intervals, respecting `--out`/`--timestamps`. Unsupported/failed queries warn once per failure streak without inventing zero or stopping packet monitoring. This additive IOCTL does not change the 0.3.3.0 event wire layout. Package/Cargo versions are separate; the monitor rejects older wire versions.
- `IOCTL_ADAPTER_INFO` uses function `0x803` / code `0x9C40E00C`, empty input, buffered read/write access, and a versioned attached-module snapshot including not-running modules. Header: four LE u32 values `(schema=1, entry_size=1760, count, running_count)`; exact successful total `16 + count * 1760`. There is no 32-adapter quota: only checked 32-bit IOCTL byte-length arithmetic bounds the count. An undersized output that holds the header gets exactly 16 bytes with `STATUS_BUFFER_OVERFLOW`/`ERROR_MORE_DATA`; outputs below 16 bytes get `STATUS_BUFFER_TOO_SMALL`. Both clients initially allocate 56336 bytes for compatibility with older schema-1 SYS builds and grow fallibly on valid sizing headers, using bounded retries for topology churn; never allocate the arithmetic maximum upfront. `driver/src/adapter_info.rs` owns the portable explicit codec/size planner and UTF-16 handling; `driver/shim/adapter_info.h` retains the asserted internal storage/FFI declarations. The diagnostic list lock protects detach lifetime, metadata and running-count consistency while copying into nonpaged staging storage; allocation, explicit wire encoding and frees happen unlocked. Header-only sizing replies allocate no staging. Bounded internal retries handle growth while staging is allocated; exhaustion returns `STATUS_RETRY`, not a bogus empty/partial snapshot. Never take an adapter/policy lock or call NDIS while holding the diagnostic lock. Identity/names/MAC come from attach, general attributes from successful restart, link values from valid link-state indications. Missing optional values have validity flags; names are at most 255 UTF-16 code units plus NUL with explicit truncation flags. Both C++ clients expose owning `AdapterInfo`/`AdapterSnapshot` and `GetAdapterInfo`, leaving output unchanged on failure. Monitor prints once at startup with `--out`/`--timestamps`; unavailable queries warn without stopping monitoring. Event version remains 0.3.3.0; do not infer snapshot availability from that version alone. No OID queries, binding changes, kernel pointers or guest ownership are added.
- `Driver::Open` opens the existing device with `FILE_FLAG_OVERLAPPED`; it does **not** wait for startup or check the version. Integrations must call `GetVersion`, as the monitor does. The constructor's `service_name` selects only the device basename. `Driver::Install` is an unsupported compatibility stub; the console and reusable clients do not load a driver. `Driver::Open` preserves its Win32 failure code in `GetLastError`.
- Console startup opens the existing device and reports failure if absent; it never creates or starts an SCM service. Without `--duration`, the session runs until Ctrl+C. A positive duration bounds monitoring, not installation. The header-only client's readiness-event startup wait remains unchanged.
- `driver/shim/driver_ready.h` shares Win32 and `\BaseNamedObjects\FirewallXNdisFilter.DriverReady` kernel names. The Rust native layer signals only after the device/timer are initialized, retains the event object/handle, then clears/closes it on unload. Event creation is best-effort (the global directory may not exist during early boot); do not fail LWF initialization for a notification failure. Rebuilt monitor alone cannot add startup signaling to an older installed SYS. Offline startup tests use fake openers/private Local test events, never the production global object.
- Opening activates a policy session and clears its event queue/cache/bandwidth. Shutdown or handle cleanup deactivates it, clears those queues, and resolves pending packets through fallback (invalidated paths still drop). To activate again after shutdown, close and reopen; shutdown neither closes the handle nor unloads/unbinds the filter.
- Nonzero reads wait for bytes in a cancel-safe queue, with no fixed waiting-IRP count or byte budget. Reads/writes have no driver-defined 65536-byte cap, only native Windows DWORD/u32 length bounds; writes remain nonempty and fully validated before side effects. One completion can coalesce records beyond 64 KiB; release PolicyLock between short internal copy chunks rather than holding it over an arbitrarily large read. Reads never succeed empty just because the queue is empty. Explicit zero-length reads still return zero. Shutdown/cleanup/unload cancel pending reads; clients must cancel/reap before releasing OVERLAPPED storage. `driver/src/native_device.rs` owns the CSQ/work item, IRP+worker rundown and client gate. Rust with_state publishes queue readiness/online state while policy-locked; only work scheduling occurs there, never NDIS calls or IRP completion. There is no idle read polling. Reads can split/coalesce records. Client 65536-byte streaming buffers are a buffer choice, not a device limit. `RecordStream` buffers one frame and grows storage fallibly for complete bandwidth groups; connection frames retain the 1048636-byte bound and log records the 512-byte bound. Invalid headers invalidate the stream until `Reset`, with no guessed resynchronization.
- `Run` starts a reader thread but blocks the caller. Event handlers run on the reader; `on_poll` runs on the calling thread; `on_warning` may run on either. Callback data is temporary. Synchronize shared state, keep handlers short, and explicitly request statistics/send verdicts; `Run` does not do these automatically.
- `RequestShutdown` only issues the IOCTL; it does not signal the `Run` stop event. `Stop` signals that event and sends shutdown once, and is safe during `Run`. Wait for `Run` to return/join before `Cleanup` or destruction; neither operation manages the installed LWF. Authorized custom clients also need a bounded runtime deadline.
